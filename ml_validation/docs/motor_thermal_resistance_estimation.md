# 정격 전력만으로 모터 열저항을 추정할 수 있는가

**결론: 가능했고, 실제로 구했다.** `R_motor = 0.0115 °C/W` (R²=0.96), 질량·재질(비열) 없이
정상상태만으로 얻었다 (§3). "얼마나 빨리 뜨거워지는가"(시간상수 C)도 §5에서 PINN에 이 R_motor를
앵커로 넣어 마저 구했고, 완전히 별개인 두 방법(정상상태 전력 회귀 vs 과도응답 곡선피팅)의 결과가
서로 겹치는 것까지 확인했다.

---

## 1. 왜 질량·재질(C)이 필요 없어지는가 — 정상상태(steady-state)의 트릭

모터를 "열이 들어오고 나가는 하나의 덩어리"로 보면 열평형 방정식은 이렇게 쓴다.

```
C · dT_core/dt = P(t) − (T_core − T_room) / R_motor
```

- `P(t)` : 모터가 실제로 열로 바꾸는 전력 (W)
- `R_motor` : 우리가 구하고 싶은 열저항 (°C/W)
- `C` : 모터의 열용량 (J/°C) — 질량 × 비열로 정해지는 값
- `T_core − T_room` : 코어와 주변(실내) 온도차

**정상상태(`dT_core/dt = 0`)** 를 대입하면 `C`가 곱해져 있던 항이 통째로 0이 되면서
**C가 식에서 완전히 사라진다.** 남는 건:

```
R_motor = (T_core_steady − T_room_steady) / P
```

"정상상태 온도차 ÷ 그때 넣어준 전력"만 알면 끝 — 질량도, 비열도, 재질도 필요 없다.

## 2. 왜 이게 지난번 PINN의 G_hat/R_loss와 다른가

지난번 PINN은 **온도 센서 두 개(T_ambient→T_core) 사이의 신호 전달**을 맞춘 것이고, 실제
전력(P)을 입력으로 쓰지 않았다. 그래서 `G_hat, R_loss, C_hat` 세 개가 서로 얽혀서(스케일을
같이 곱해도 궤적이 똑같이 나와서) 개별 절대값을 못 뽑았다.

이번 방법은 **진짜 물리량인 P(전력, W)를 직접 넣는다.** 미지수가 `R_motor` 하나뿐이라
얽힘(비식별) 문제 자체가 생기지 않는다 — 완전히 별개의, 더 단순하고 더 믿을 수 있는 계산이다.

## 3. 실제 계산 결과 (2026-08-26)

### 앵커: Labvolt 8960 정격 전력

장비가 **Labvolt 8960 시리즈**(8960-10 포함 — 뒤 숫자는 전압/언어 리전 코드일 뿐 하드웨어는
동일)로 확인됨. 데이터시트 상 **정격 전력 350W(dynamometer 모드)**.

### 절차

1. run마다 `T_core(t) = T_inf − (T_inf−T0)·exp(−t/τ)` 단일 지수함수로 피팅해 **진짜
   정상상태(T_inf)를 외삽**한다 — 짧게 끝난 run도 곡선 모양으로 복원할 수 있다
   (`scripts/fit_motor_thermal_resistance.py`).
2. `load_pct → P`는 정격 350W 기준으로 환산 (25%→87.5W, 100%→350W, ...).
3. `dT_inf = a + R_motor·P` **절편 있는 회귀**로 피팅한다. 원점을 강제로 지나게 하지 않은 이유는
   §3.1 참조.
4. 200% 과부하 run은 로그 길이(560s)가 다른 run들의 시상수(~1000~1400s)보다 훨씬 짧아 T_inf
   외삽이 못 미더워서 회귀에서 제외했다(그래도 그래프엔 참고용으로 표시).

### 3.1 절편이 필요했던 이유 — 확인된 물리적 사실

처음에 원점을 지나는 단순 `R=ΔT/P`로 부하마다 따로 계산해보면 0.18 → 0.04 °C/W로 **4.7배나
흔들렸다.** 이유는 **0% 부하에서도 ΔT가 이미 14°C 가까이 올라가 있었기 때문.**

**확인 결과: 다이나모미터는 0% 부하에서도 정격속도로 계속 회전하고 있었다.** 즉 0%는 "꺼짐"이
아니라 "무부하 정격 회전"이다 — windage(공력저항)·베어링 마찰·철손이 부하(토크)와 무관하게
항상 열을 만든다. 그래서 절편 `a`를 자유롭게 두고 회귀해 **부하와 무관한 베이스라인 발열(a)**과
**부하 1W당 추가로 오르는 온도(R_motor)**를 분리했다.

## 4. "얼마나 빨리"는 여전히 C가 필요했다 — 그런데 이것도 끝냈다

R_motor(정상상태, 최종 온도)와 C(과도상태, 도달 속도)는 서로 다른 정보다.

- **R_motor만으로 답 가능**: "이 부하로 계속 돌리면 결국 몇 °C까지 올라가나?" → §3에서 확정됨.
- **C도 있어야 답 가능**: "위험 온도까지 몇 분 남았나?" — 화재예방 조기경보의 핵심 질문.

**R_motor가 실제 단위로 고정됐으니**, `train_pinn_real.py`의 3개 미지수(`G_hat, R_loss, C_hat`)
중 `R_loss`를 이 값으로 앵커링해서 `C_hat`을 다시 학습시켰다 — 결과는 §5.

## 5. R_loss 앵커링 결과 (2026-08-26 완료)

`PhysicsParams`에 `fixed_r_loss` 옵션을 추가해 `R_loss=0.0115°C/W`로 고정하고 `G_hat, C_hat`만
학습하도록 바꿨다 (`train_pinn_real.py`). **첫 시도는 발산했다** — 초기값(G_hat, C_hat≈0.5)이
자기보정 스케일용이었는데 R_loss를 실제(작은) 값으로 고정하니 손실항이 ~1300배 커져서 8000
epoch로는 못 따라갔다(MAE 8.96로 오히려 악화). **초기값을 실제 스케일 근처(G_hat=50,
C_hat=100000)로 주고 epoch을 30000으로 늘리니 바로 수렴**했다.

| 모델 | MAE (unseen 75%/150%) |
|---|---|
| (A) 데이터만 | 0.73°C |
| (B) PINN, R_loss 자유학습 | 0.59°C |
| **(C) PINN, R_loss=0.0115 앵커링** | **0.54°C (최고)** |

**가장 중요한 확인**: (C)에서 학습된 `C_hat ≈ 100,000 J/°C`가, §3~4와 완전히 무관한 방법(run별
지수함수 외삽 τ ÷ R_motor)으로 구한 범위 **[86226, 119730]에 실제로 들어간다.** 서로 다른 두
방법(정상상태 전력 회귀 vs 과도응답 곡선피팅)이 같은 답에 수렴했다는 뜻이라, 우연히 맞춘 숫자가
아니라는 근거가 된다.

부수 관찰: `G_hat`은 학습 중 거의 0으로 수렴했다 — T_ambient는 애초에 실제 "전력 입력"이 아니라
상관된 대리 신호이므로, 물리항의 실질적인 제약은 R/C 이완항이 다 하고 있다는 뜻이다. 문제라기보다
다음에 살펴볼 관찰 포인트로 남겨둔다.

재현: `python scripts/train_pinn_real.py` (3-way 비교 전체 출력),
`notebooks/02_pinn_shf_real_data.ipynb` §5에도 실행된 상태로 들어있다.
